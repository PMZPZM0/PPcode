# PPcode v0.1.19 发版说明

本版主题：**更新体验的三处硬缺陷**（提示关不掉 / 镜像龟速 / 差分永远不生效）。

## 一、修了什么

### 1. 更新提示关不掉

后台下载时的常驻进度卡**没有任何关闭入口**。修法：右上角加收起键 —— 收起只影响显示，下载继续跑；下载结束 / 换版本 / 进入安装阶段会自动恢复显示。全屏安装遮罩不受影响（那层是「正在安装，别重复启动」的保护，不该被关掉）。

### 2. 镜像下载龟速

按实测 4MB Range 吞吐重排候选序（`electron/gh-mirror.ts`，全局唯一真相源）：

| 通道 | 实测吞吐 | 处置 |
|---|---|---|
| 直连 GitHub | 本机不可用（空响应） | 保留第一档，失败即快速回落 |
| `ghfast.top` | **0.82 MB/s** | 提到第二档 |
| `gh-proxy.com` | 0.42 MB/s | 第三档 |
| `hk.gh-proxy.com` | 302 后不可用 | 第四档 |
| `ghproxy.net` | 0.014 MB/s（≈0.8MB/分钟） | 已在候选外 |

### 3. 差分更新永远不生效

根因不是「没有基线」这么笼统，而是**缓存配对坏掉且不会自愈**：

- electron-updater 的 NSIS 差分靠成对缓存：`<updater 缓存目录>/installer.exe` + 同目录 `current.blockmap`；
- 只要其中一份缺失，配对就失效 ⇒ 只能下整包，而且这个状态**永远不会自己修好**；
- 更致命的一处：差分下载时 `autoInstallOnAppQuit` 被显式设成 `false` —— 下载完不点「重启安装」，用户一关应用，updater 句柄就没了，安装退回 spawn（不经 updater 安装器）⇒ 配对缓存永远写不回去。

修法：
- `healDifferentialCache()`：下载前**缺任一份就两份都删**（只动自家 updater 缓存目录，⛔ 不碰安装目录与用户数据），让 updater 重新拉整包并写回成对缓存；
- `autoInstallOnAppQuit = true`：不点按钮、直接退出也由 updater 装完并写回缓存；
- `hasDifferentialBaseline()`：本机是否有成对基线，供界面按实际情况提示。

**必须说清的口径**：NSIS 差分没有「从安装目录反推基线」的能力，基线只能来自「上次由 updater 完成安装」。所以缓存重建后 **本版仍是整包**，从 **v0.1.20 起** 同一条安装线才会只下变化块。

## 二、mac 适配审计结论

本轮改动集中在 `electron/updates.ts`、`electron/gh-mirror.ts`、`electron/features/updates-ipc.ts`、`src/features/app-view/AppView/UpdateFlowBanner.tsx`、`src/styles/37-update-ready.css`。差分与镜像逻辑均在 `process.platform === "win32"` 门控内（mac 直接抛 `differential_unsupported_platform` 走完整包）。

`node scripts/mac-audit.mjs`（`v0.1.18..HEAD`）命中 **49 条**，逐条判读：集中在 `exe` / `win32` / `darwin` / `winpath` / `appdata` / `backslash` / `powershell` 七组，全部落在 **Windows 专属路径**（`artcraft.ts` 的 Craft Launcher 安装探测、外部语音引擎的 Windows 分支）、**平台门控内**或**守卫断言夹具**（`scripts/guards/*`）；mac 走不到这些分支。**本轮新增行 0 命中**。

## 三、mac 首次打开自救（带路径）

1. 在「下载」里双击解压；
2. 把 App 拖进「应用程序」；
3. 首次打开若提示"无法验证开发者"：右键 →「打开」；或把 App 图标拖进终端自动填好路径后执行：
   ```bash
   xattr -dr com.apple.quarantine "/Applications/PPcode.app"
   ```
4. 错误码 640 表示系统仍在隔离态，重复上一步即可。

mac 更新：**每次都是完整包**（无 NSIS blockmap，不是漏做）。

## 四、组件版本体检与名称 / 打包 / 发版核对

- 引擎 `@openai/codex` 与随包工具表本轮未变（与主仓 v0.0.64 的体检结论一致）；
- 版本对齐 4 处：`package.json` / `package-lock.json`（根 + `packages[""]`）/ `whats-new-notes.ts` / 本文件；
- 品牌面保持 PPcode 原样（`productName` / `appId` / 图标 / 侧栏品牌名均未动）；
- Windows 仍发 `exe + exe.blockmap + latest.yml` 三件（CI 对 `latest.yml` 的 `path` 有硬断言）。

## 五、已知问题

- 本版新装/升级仍是整包（缓存重建）；差分的「几十兆」从 v0.1.20 起可见。
- 若中途手动装 exe（不经应用内更新），配对缓存会再次缺失，下一版又回整包。
- 收起键只作用于后台下载提示；全屏安装遮罩不可关闭。
