# v0.1.3 发版说明

本版主题：**语音播报收干净**（停止真停 + 每回合限长 + 状态条重做），外加工具链在线更新与自动化通道修正。

## 一、修了什么

1. **语音播报：点「停止」现在真的停**
   - 现象：按了「停止」之后播报还在继续；模型越是勤快插播，越按不住。
   - 根因：停止逻辑过去只掐断了「此刻正在响的音频」和「队列里已排好的」，但**三条入口仍然活着**：
     ① 「本回合要念正文」的标记没清 ⇒ 下一句正文到达照常合成照常念；
     ② 自动播报的计数器没重置 ⇒「单回合工具调用 > 10 次 / 同一处返工 ≥2 次」硬规则下一帧又命中；
     ③ 模型的插播工具不受管 ⇒ 模型再调一次，无条件入链。
   - 修法：引入**静音闩锁**。按停时同时掐掉上面三条，之后所有播报（正文实时 / 插播 / 结束播报稿）在**唯一入口**被拦下。闩锁只在两处解除：状态条上的「**恢复**」按钮，或把播报总开关重新打开。
   - ⛔ 刻意**不**跟回合结束自动解除——用户按停的语义是「我现在不想听」，下一回合又自动开口等于白按。

2. **语音播报：每回合限长**
   - 现象：播报动辄一两分钟。
   - 根因：原先只有「队列长度」上限，而正文朗读是一条**无界流**——一旦触发全文朗读，正文吐多少念多少，队列永远不满，背压形同虚设。
   - 修法：新增**每回合 160 字总预算**（三种播报共用），超出不再念并关掉本回合的正文朗读；播报稿上限 240 → **120 字**；插播工具 120 → **80 字**；引擎侧指令同步收紧（~80 → ~50 字）并写明「超出的部分根本不念」。

3. **语音播报状态条视觉重做**
   - ⛔ **停止按钮漏了 `appearance: none`** —— 全站无 `color-scheme` 声明，暗色下原生按钮由浏览器按浅色 UA 绘制，在深色胶囊上是一块突兀的白块；
   - ⛔ **条子宽度被写死至少 280px** —— 没有正文时就是一条空胶囊 ⇒ 改为贴合内容；
   - 点击区 22 → **32px**、字号 11.5 → 12px、底色与输入框错开、补键盘焦点环与「减弱动效」支持；
   - 文案去掉重复的「正在」二字（呼吸圆点 + 喇叭图标已表达）。

4. **技能 / 插件 / 自动化工具在线更新**
   - nuphus（桌面自动化）与 browser-skill（浏览器自动化）：走「用户配置的 registry → 国内镜像 → 官方源」依次尝试；
   - 技能：按内容指纹逐文件比对（SHA256），只提示真正有变化的部分；插件：按版本号比较。

5. **浏览器 / 桌面自动化改走命令行通道**
   - 现象：任务跑到一半自己断了，伴随 `unsupported call` 报错。
   - 根因：当前引擎版本把内置 MCP 工具**延迟暴露**给模型——工具列表里看得到，一调用就报不支持。此前指令却把 `browser_*` 写成「首选」，弱模型不会去核对工具列表，直接照首选调 ⇒ 失败 ⇒ 换招重试 ⇒ 整个回合耗死在工具选择上。
   - 修法：主线改为命令行通道（`playwright-cli` / `nuphus-call`），并明确要求失败立即切换、不要重试。

6. **引擎升级到 0.162.1**：npm 声明与实际二进制版本对齐，防止重装时被回退。

## 三、安装

**Windows**：下载 `PPcode-0.1.3-win-x64.exe` → 双击安装（覆盖安装无需先卸载；若旧版在运行，安装器会先关掉它）。

**macOS**：下载对应芯片的 `PPcode-0.1.3-arm64-mac.zip`（Apple 芯片）或 `PPcode-0.1.3-x64-mac.zip`（Intel）→ 解压 → 把 **PPcode.app** 拖进「应用程序」。

首次打开若提示无法验证开发者：

1. 打开「终端」，输入 `xattr -cr `（**末尾有空格**）；
2. **把 app 图标拖进终端**——自动补全路径（用户往往不知道自己的路径）；
3. 回车执行，再双击打开。

若提示已损坏（错误码 640）：同样是上面的 `xattr -cr <路径>` 命令，执行一次即可。仍打不开时：系统设置 → 隐私与安全性 →「仍要打开」。

每个安装包同目录都有同名 `.sha256.txt`，可校验下载完整性。
